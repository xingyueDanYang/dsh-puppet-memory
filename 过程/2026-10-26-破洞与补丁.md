# 2026-10-26 破洞与补丁

> 当天发现、当天就补的五个洞。不是「该记住的道理」，是「已经修掉的破损 + 留下的检查」。
> 给以后的人（和以后的自己）看：同一类洞下次怎么提前发现。

## 一、默认值会替你说话

**洞**：`DEFAULT_PERSONA` 里写死了「用户叫我『大肥鱼』」，`ensure()` 在 `persona.md` 缺失时会写进用户的记忆目录——等于任何人装这个插件，他的 AI 都默认管主人叫大肥鱼。还带着我们的偏好原话。

**补**：模板改中性占位「把用户第一次告诉你的叫法写在这里」；已有 `persona.md` 不覆盖（只在缺失时写）。

**留下的检查**：`test/fresh-persona.mjs` 7 项——新装人设不含旧称呼、含占位提示、已有 persona 不被覆盖。

## 二、有检查 ≠ 检查生效

**洞**：`脱敏检查.mjs` 里「本机绝对路径」「家目录路径」两条正则把反斜杠写成 `\\\\`（正则里是两个反斜杠），而文档里是单个 `\`，所以这两条**从来没命中过**；更严重的是 `git ls-files` 默认把中文文件名转成八进制转义，`给人类的说明书.md`／`全功能说明.md`／`验收-*.md` 读不到，读失败又被 `catch { continue }` 静默跳过——13 个文件从来没被扫过。打包后人工扫才发现真实群号还在《全功能说明》里。

**补**：正则改单反斜杠 + 负向前瞻排除占位符；`listFiles()` 改用 `git ls-files -z`；读不到的文件不再静默，点名报出；检查脚本自身加入跳过集（只有它自己）。

**留下的检查**：preflight 第 20 项「包内容隐私扫描」自动跑它；负测验过——往中文名文档插真实群号立刻变红。

## 三、读者看到的第一句话是旧的

**洞**：README 开头「当前最新发布为 `0.32.0`」从 0.33/0.34 两次发版都没改。而「文档版本号」检查抓不到它：那项只要求文档里**出现**当前版本号，更新日志里有 0.34.0，所以照样绿。

**补**：首行改成当前版本；preflight 加一条专项检查——从 README 正则取「当前最新发布为 `X`」，与 `package.json` 比对，不一致就红。

**留下的检查**：负测验过——改回旧版本号立刻变红。

## 四、会话索引的定位列全是空的

**洞**：`array/sessions.jsonl` 的 `sessionFile` 一列 131 行全是空串。原因不是没写，是写入时把 `header.id`（本身已带 `session-` 前缀）又拼了一个 `session-`，去找 `session-session-<uuid>`，永远找不到；目录布局还有两代（旧版裸 uuid、新版带前缀）。

**补**：`findSessionFile` 两种 id 写法 × 两种目录布局都试，顺带认 IM 会话的冒号转义；导出函数供测试。

**留下的检查**：`test/session-file.mjs` 11 项；本机实测老逻辑 0/16 个会话能定位，修好 15/16。

## 五、单文件会越用越慢，导出会越住越大

**洞**：会话索引 `array/index.jsonl` 是单文件（6 个月会到十几 MB），而日记早就按月分片——两份数据切法不一致，慢的正好是没切的那个；另外导出档案住在记忆目录里，两次导出就占记忆体积 37%。

**补**：会话索引改按月分片（与日记同一套切法），读侧合并老文件 + 月份文件，首次运行自动迁移并留档；导出默认输出改到 `~/.dsh/memory-exports/`；检索加日记月份预筛（只有多月份才启用，无候选退回全扫）。

**留下的检查**：`test/array-split.mjs` 11 项（迁移/幂等/留档/读侧/新写入）；实测检索 26.9 → 20.7 ms、记忆目录 5.17 → 3.38 MB；`eval-recall` 持平。
