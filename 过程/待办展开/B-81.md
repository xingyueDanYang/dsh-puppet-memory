## 内容

**市场条目的版本与宿主要求声明**（候选，2026-10-27 丹阳看图时定：「版本号还没做，下次更新一块吧」）。

**现象**：插件市场卡片显示「**宿主要求未知**」、条目不显示版本。查过市场侧逻辑（`dshmarket/client/client.js`）：`basis==="undeclared"` 才显示「未声明」，我们是 `basis:"unavailable"`——**市场没读到我们的声明**（不是没写）。我们的 `package.json` 里其实有 `engines.dsh >=0.2.1-rc.2`；条目 yml 只有 url/name/category/tarball/description/icon（同类条目也没有）。

**原做法设想**：下次发版时①在市场条目补版本与宿主声明字段（字段名从 dshmarket 的 schema/校验里查，别猜）②发完看卡片是否变成「符合宿主要求（依据声明）」；顺带核对「已安装」与 latest 指向一致。**不急，随 0.37 一起**。

**【2026-10-27 更正·解法变了】** 丹阳指正：**市场只统计 npm 的元数据**——版本与 `engines` 都是从 npm registry 读的。我们的包**从来没发上 npm**（首发一直冻结，政策是「解冻后只试一次，不行就放弃」），所以显示「宿主要求未知」是**必然结果**，不是条目写漏了。

**解法三选一**：①若市场条目 schema 支持手写声明，就在条目里写（首选，不动 npm）；②解冻 npm 发一版（与既定政策冲突，不推荐只为这个解锁）；③接受现状，卡片显示未知。

**【2026-10-27 查过了：①走不通】** 上游 `awesome-dsh-plugin/contributing.md` 明文写：npm 映射「**不需要通知我们，从 registry 自动采集；条目里没有任何字段需要填，手写 `npm:` 会被校验拒绝**」；同时「没有 npm 包也一样：条目照常工作，只是没有下载量数字」。所以：手写声明被规则禁止，解冻 npm 又不做 → **只接受现状**（卡片显示「宿主要求未知」、没有下载量数字）。这不是缺陷，是我们不发 npm 的必然结果；`engines` 仍写在 `package.json` 里，对实际安装与兼容性判断不起作用，只是卡片上不显示。

## 结论

**不做，记结论**。除非哪天重启 npm 首发，否则卡片上永远显示「宿主要求未知」。

卡片上能看到版本与「符合宿主要求」；改完不影响任何已安装插件。
