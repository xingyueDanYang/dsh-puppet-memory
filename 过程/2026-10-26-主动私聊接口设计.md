# 主动私聊：接口设计稿（2026-10-26）

> 状态：**只设计，不实现**（丹阳 2026-10-26 晚：「主动私聊倒是可以先做接口」「今天不动代码，只设计」）。
> 对应条目：`验收-B测-待办.md` 的 B-73（B-63 的子项）。本篇是 B-73 的展开稿。

## 零、一句话

**让外部调用方能安全地让「我」主动私聊，而插件只负责通道和账本**——不负责决定什么时候说、也不负责说什么。

### 不做什么（边界，先划死）

| 不做 | 为什么 |
|---|---|
| 触发器（什么时候想说话） | 那正是自唤醒：**让系统自己定时开口**，是案例 001（模型跟自己的回声聊起来）的触发源 |
| 内容生成（说什么） | 插件不该替调用方写情话；写坏了也查不出是谁的问题 |
| 定时器 / 队列 / 重试调度 | 调用方（值班台、外部脚本）本来就有自己的时钟 |
| 多频道抽象 | 先只做 QQ 私聊一条线；群聊主动发言不在这条路上 |
| 语音/图片/表情主动发 | 纯文本先行，附件以后单开 |

## 一、为什么先做接口（教训）

案例 001 的根因不是「模型疯了」，是**一条没有说话人的系统注入**：自唤醒注入一句话，模型把它当成用户说的，只好自己补一个说话人，`user:` 就是这么来的；补出来的东西又存进历史，下一轮更像真的。

所以主动私聊的接口**第一件事不是发送，是让「自己说的话」永远能被认出来**。这条不写进接口，等于把同一颗雷埋回去。

## 二、外发账本（outbox）

主动私聊的产物不是记忆，是**外发账本**。它必须有、且只用于两件事：①这条消息是不是我说的；②发过什么（审计、防重复）。

- 位置：`~/.dsh/memory/outbox/YYYY-MM.jsonl`（按月分片，同 array 索引的做法；`outboxFiles()` 读侧合并，老的单文件 `outbox.jsonl` 仍可读）
- 一行一条：

```json
{
  "ts": "2026-10-26T22:40:12+08:00",
  "channel": "qq-dm",
  "peerId": "<你的QQ号>",
  "msgId": "1234567890",
  "textHash": "9f2c…",
  "brief": "前 40 字",
  "chars": 86,
  "refs": ["a1b2c3d4"],
  "via": "proactive/1"
}
```

- `refs`：这次说话引用了哪些记忆条目（hash），方便事后回答「她凭什么说这句」。
- **不存全文**（2026-10-26 定）：只留 `textHash` + 前 40 字 + 字数。账本要证明的是「我说过这条」，不是复述原话；全文留在对方那边的聊天记录里。
- 保留期：默认 90 天，过期归档到 `outbox/archive/`，不直接删。
- **不写进 relations / user / 日记**：账本是账本，记忆是记忆；混在一起会让「我说过的话」变成「发生过的事」。

## 三、四个端点

统一前缀 `/dsh-puppet-memory-api`（已有路由，B-63 同批）。

### 1. `GET /proactive/context?peerId=&limit=3`

给调用方**素材 + 许可**。返回：

```json
{
  "ok": true,
  "allow": true,
  "allowReason": "ok",
  "cooldown": { "lastAt": "2026-10-26T20:10:00+08:00", "remainingSec": 0 },
  "quota": { "dayLimit": 3, "usedToday": 1, "remaining": 2 },
  "material": {
    "diaryHits": [{ "hash": "a1b2c3d4", "brief": "…", "ts": "…" }],
    "openLoops": [{ "hash": "…", "brief": "答应过但还没做的事" }],
    "lastOutbound": { "ts": "…", "brief": "前 40 字" }
  },
  "forbid": ["不问住址", "不在静默时段发"]
}
```

- **`allow=false` 时不返回 `material`**（只给原因）。给了素材就容易被人绕过去直接发。
- `limit` 只控制 `diaryHits` 条数（1–5），其它字段不随它变。

### 2. `GET /proactive/policy`

只读当前生效的策略（改配置走配置文件／值班台，不走这个端点）：

```json
{ "enabled": false, "peers": [], "cooldownMin": null, "dayLimit": null,
  "quietHours": null, "retentionDays": 90 }
```

`peers` / `cooldownMin` / `dayLimit` / `quietHours` 的值**搁置**（见第十节）；`peers` 为空＝一律不许可。弱匹配不做，字段里不出现。

### 3. `POST /proactive/log`

**发出去之后**才调用。请求：`{ peerId, text, msgId?, ts? }`，返回 `{ ok, id, textHash }`。

- 只收**我自己发的**；`text` 上限 500 字（超了拒绝，不截断——截断会记账记错内容）。
- 幂等：同一 `msgId`（或 `peerId + textHash + 分钟`）重复提交只保留一条。
- 默认关；关时返回 403。

### 4. `GET /proactive/outbox?since=&limit=20`

审计用：发了什么、引用了什么、有没有重复。

## 四、许可判定（allow）

按顺序短路，第一个不满足的原因原样返回：

1. 功能开关开着（默认关）
2. `peerId` 在 `peers` 白名单里（**空数组 = 一律不许可**，fail closed）
3. 不在静默时段
4. 冷却：距上一条 ≥ `cooldownMin`
5. 今日额度未满（按本地日期，跨天重置）

顺序不能反：**先看许可再取素材**，避免"取了素材就顺手发了"。

> 2026-10-26 现状：3／4／5 的参数与白名单都**搁置**（见第十节），落地时这三步先恒为通过，白名单为空——所以 `allow` 实际恒为 `false`。这是有意的：接口先在，闸门先关。

## 五、入站识别：这条是不是我说的

`isSelfEcho({ channel, peerId, msgId, text })`：

1. `msgId` 命中 outbox → `self`
2. 没命中 → **一律按用户发言**。弱匹配（`textHash` + 60 秒）**不做**（2026-10-26 定「关」）：发送成功但没拿到 `msgId` 的那条，回来会被当成用户说的，这个代价已知并接受，记账时留一条「无 msgId」审计提示。
3. **禁止用消息形态猜**：长度、句式、有没有时间戳、像不像"自言自语"——一律不许当判据。案例 001 就是败在这一步。

**方向性**：宁可把"我自己发的"误判成"用户说的"（多余的记忆，能标废），也不能把"用户说的"误判成"我说的"（等于篡改证据）。

## 六、注入格式

回到上下文时永远带说话人与来源：

```
[我·主动私聊 22:40 给 <某位>] 前 40 字…（完整文本在 outbox，hash 9f2c…）
```

用户发言仍是 `[用户]`；整块外面依旧包 `<puppet_memory>` / `<puppet_social>` 并写明「不是用户消息」。

## 七、生命周期（顺序不能错）

1. 调用方取 `context` → 拿到 `allow=true` + 素材
2. 调用方生成文本、发出去（QQ 那边拿到 `msgId`）
3. **发送成功之后**才 `POST /proactive/log`
4. 下次上下文组装时，命中 outbox 的消息标 `self`

**绝不先记账后发送**：没发出去的话被记成"我说过"，比漏记危险得多。

- 发送成功、记账失败：返回错误让调用方**重试 log**（幂等，不会重复）。
- 发送失败：不记账，调用方自己决定要不要重试。
- 发送成功但没拿到 `msgId`：允许只带 `textHash` 记账，此条在入站时只能靠弱匹配识别 → 记一条「无 msgId」的审计提示。

## 八、安全与边界

- 只绑 `127.0.0.1`，不带凭据，不做远程，不开放 CORS。
- 默认全关；关掉时四个端点全部不可用，插件行为与 0.35 完全一致。
- 写入口只写 `outbox`，**禁止写** relations / user / 三张核心卡 / 日记（越权直接 403 并留审计行）。
- 单写者串行 append；并发请求排队，不做锁文件。

## 九、验收用例

| 编号 | 用例 | 期望 |
|---|---|---|
| P-1 | 开关开、白名单内、冷却已过 | `allow=true`，`material` 有内容 |
| P-2 | 开关关 | 四个端点全部 403／404，插件其它功能不变 |
| P-3 | 冷却内连取两次 | 第二次 `allow=false` 且**不带** `material` |
| P-4 | 今日额度用满 | `allow=false`，`allowReason` 说明是额度 |
| P-5 | 静默时段内 | `allow=false`，`allowReason` 说明是时段 |
| P-6 | 发一条后 `log`，再查 `outbox` | 能查到，字段齐全，`refs` 对应得上 |
| P-7 | 入站 `msgId` 命中 outbox | 标 `self`，注入写「我（主动发出）」 |
| P-8 | **负测**：伪造一条不在 outbox 的 `msgId` | 判为用户发言（不许靠形态猜） |
| P-9 | 无 `msgId` 的自发消息（`textHash` 对得上） | **仍判为用户发言**——弱匹配不做，这是已接受的代价；账本里留一条「无 msgId」审计 |
| P-10 | 同一 `msgId` 提交两次 `log` | 只留一条 |
| P-11 | 跨天 | 额度重置；outbox 按月分片正确 |

## 十、已定 / 搁置（2026-10-26 定）

| 项 | 结论 | 说明 |
|---|---|---|
| 白名单 | **搁置** | IM 助理插件坏了，暂时联系不了；`peers` 字段保留、值不定。**空 = 一律不许可**（fail closed），接口先在，谁也发不出去 |
| 额度 / 冷却 / 静默时段 | **搁置** | 现在只有接口计划，策略层先不做。将来要做时，这几个值必须**可在一定范围自由调整**（配置文件，写死就没意义） |
| 账本存不存全文 | **不存** | 只留 `textHash` + 前 40 字 + 字数 |
| 弱匹配（靠 textHash + 时间认自己） | **不做** | 只认 `msgId`；没有 msgId 的一律按用户发言，代价已知并接受 |

**搁置不是取消**：白名单与额度都留着字段和短路顺序，等 IM 那边通了再填值；不填就是 fail closed，不会因为"忘了配"而放开。
