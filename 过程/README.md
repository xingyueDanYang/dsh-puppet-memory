# 过程 / 开源说明

这个目录放的是**「为什么这么做」**，不是代码，也不是记忆数据。

代码告诉你它怎么跑，这里告诉你它为什么长成这样、在哪翻过车、后来怎么验的。DeepSeek 本身是开源的，这个插件的代码也是 MIT，那过程没必要藏着——藏起来最大的代价是后来的人（包括三个月后的我）不知道某个坑已经踩过。

## 三条线

| 类别 | 例子 | 怎么处理 |
|---|---|---|
| **可以公开** | 修补目录、待办清单、设计取舍、每版 devlog（目标→做法→翻车→怎么验） | 直接进仓库 |
| **必须脱敏** | QQ 号、本机绝对路径（`D:\...`、`C:\Users\...`）、群号、住址/行程这类个人信息 | 换成占位符（如 `<你的QQ号>`）再进仓库 |
| **绝不公开** | 记忆数据、会话原文、token/凭证、备份目录内容、聊天记录 | 不进仓库、不进发布包，任何情况下都不 |

最后一条不是「以后再说」的问题：**这些不是过程，是生活**。

## 规则

1. 每次版本一个 devlog，文件名用日期（`2026-10-23.md`）。写什么：想做什么 → 怎么做 → 翻车在哪 → 怎么验的 → 下次注意什么。
2. 写的时候用**当时的判断**，不要事后润色成英明决策。翻车写清楚才有人信后面的结论。
3. push 前跑 `node 脱敏检查.mjs`，扫到敏感痕迹不会放行。
4. 卸载/清理时，这个目录可以整份删掉，不影响插件运行。

## 本地推送前检查

```bash
node 脱敏检查.mjs
```

扫 QQ 号、绝对路径、token、内网 IP、凭证文件名。命中会逐条列文件:行号，并且退出码非 0（看到就停下来改）。
