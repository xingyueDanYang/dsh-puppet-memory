# 2026-10-24 · 值班台（还有两个被它带出来的坑）

## 想做什么

宿主升到 0.2.1-rc.3 之后，侧栏多了一个「更多」菜单（`sidebar.panellist.actions`，没人注册就不显示）。QQ 观察器、B站值班、记忆状态这三样心跳平时分散在三个地方，想要一眼看完，所以做一个「值班台」面板。

## 第一版怎么做的（错了）

按当时对契约的理解：往 `sidebar.panellist.actions` 注册一行自带 `button`，点击里调 `ctx.layout.selectPanel('puppet-duty-board')`；再往 `main` 注册同 key 的面板。

数据接口是好的（`?action=duty-board` 返回三块 JSON），重启后也确认了注册项 active——**但界面上是一块白块，点它没反应，侧栏也没多出任何一行**。

## 翻车在哪

1. **注册错 slot**。`sidebar.panellist.actions` 只是「更多」菜单里的**自定义行**；侧栏面板列表（连同固定的状态）读的是 `sidebar.panellist`。所以面板永远进不了侧栏，「固定」也无从谈起。
2. **自己画的按钮进不了宿主的菜单**。菜单里的行要用宿主 `MenuItemButton` 画，自己塞一个带背景色的 `<button>`，在菜单里就是一块白块。
3. **`ctx.layout` 根本不存在**。动态 client 半边的 ctx 只有 `get / on / provide / effect`（`cordis_inspect_query` 的 Builtin 清单写着），点击里那句调用被 try/catch 吞掉，于是点一下什么也不发生。
4. **面板页要自己承担尺寸**。`main` 里渲染的是裸组件，没人给你 `height:100%` 和内边距，第一版就贴在窗口边缘。

## 怎么查实的

- 宿主代码在 `resources/app.asar` 里。asar 只是「头 + 内容」的拼装格式，自己写几十行 Python 就能按 offset 取出任意文件（不依赖 asar 工具）。
- 侧栏的实现在 `@deepseek-ai/dsh-client-ui-sidebar/lib/client.js`：`usePanels` 从 `entriesOfSlot("sidebar.panellist")` 派生，`PanelMoreMenu` 把 `entries / onOpen / onPinnedChange / onDismiss` 交给菜单行。
- `@deepseek-ai/dsh-client-ui-plugin-manager` 里有一个可以直接抄的样板：`ctx.slots.inject("sidebar.panellist", () => ctx.slots.register({...}, PluginsPanelIcon))`，图标 occupant 收 `{ size }`。
- 「能不能 require 宿主原语」这件事也有答案：`dsh-client-modules` 的 `staticModules` 里就是 seed 表，`@deepseek-ai/dsh-client-ui-primitives` 在表里，所以可以 require（保险起见外面还是包了 try/catch）。

## 顺带挖出来的老毛病

`index.js` 里 `const compactionPending = new Map();` 被上一处补丁粘进了前一行注释的末尾，整句成了注释。于是每次压缩事件都 `ReferenceError`——压缩记录这条链其实是断的，只是没人看日志。`test/compaction-records.mjs` 一跑就露馅（24 项全挂）。把它拆回两行就恢复了。

教训：补丁脚本插入代码时，锚点行尾有没有换行要当回事；跑测试比看代码可靠。

## 怎么验的

- 20 套测试全过（`test/*.mjs`，用 Electron 当 node 跑）。
- 重启后用户实测四项：①侧栏出现「值班台」行；②点开三张卡片都有值；③「更多」里两行是原生菜单样式；④第二行点一下能把侧栏那行收进「更多」（用户回「可以收进去」）。
- 顺手把日志尾部的时间戳从 UTC 换成本地——之前 15:01 的扫描显示成 `07:01Z`，看着像 8 小时前。

## 发版这次的两个新坑

1. **`tar.exe` 处理中文路径会炸**（Node 传参时编码被混着解释：目录名变乱码、zip 只有 22 字节）。中文名群发 zip 是后来加的、从没跑过的分支，第一次跑就把整个发版流程带崩。现在整块包在 try 里，失败只跳过群发版，英文 zip 照常发。
2. **GitHub 的 main 和本地是两条线**：之前 0.29.1 是走 API 直接往 GitHub 传文件的，本地主线没有那几个提交，`git push` 被拒。用 `git merge -s ours github/main` 把远端历史接进来（内容以本地为准），才顺成快进推送。
