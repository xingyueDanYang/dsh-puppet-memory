# 取词器与提词器 · 设计稿（2026-10-29 丹阳定方向）

> 状态：**设计稿，未实现**。本文只写「怎么做、怎么算过」，不写代码。
> 起因：注入是硬伤——实测 40 回合里检索几乎 100% 命中，但只有 50%（改良判据后 75%，其中九成是同轮上下文重复）真被用到。
> 结论：**问题不在「检索得不够快」，在「取来的东西是不是回忆」。**

## 0. 一句话

**取词器负责「取」，提词器负责「判断取来的内容构不构成回忆」**；「重要」不是一次认定的，是**被丹阳反复确认出来的**。

## 1. 两个角色

| 角色 | 职责 | 不做 |
| --- | --- | --- |
| **取词器**（cue picker） | 从「你这句话」里取词 → 撞记忆 → 出候选（**先事件总结**，再重要库，空了再常规库；事件最多占 2 个候选、要两个词重合——丹阳 2026-10-29 定顺序） | 不判断真假、不算计分 |
| **提词器**（prompter） | 研判候选「算不算回忆」、处理多义、决定「怎么说」、把结果变成自然语言 | 不负责检索、不改记忆内容 |

产出形态：**像正常回复**——不贴块、不列资料、不出现 `<puppet_*>` 标记；靠措辞体现"我想起一件事"。

## 2. 记忆两分：常规 / 重要

- **常规记忆**：现有各层照旧，正常检索。
- **重要记忆**：单独存放 `deep/important.jsonl`；**常规检索默认不再检索它**（避免同一件事被检索两次、占两次预算）。
- **兜底**：常规检索**零结果**时，允许再扫一遍重要库（丹阳 2026-10-29 定：「可以再取」）。
- 重要记忆**进备份、导档案**，但不进 guide 索引（避免把「重要」污染成第二套检索）。

### `deep/important.jsonl` 字段

```jsonc
{
  "id": "imp-20261029-0001",
  "topic": "邮件被批了两次",              // ≤24 字，这件事的短名
  "refs": ["<条目 hash>", "..."],         // 指向原始条目（日记/关系/笔记/常言都可以）
  "where": "deep/workbook/…|behavior/diary/…", // 一手在哪（门牌，见 B-93）
  "count": 3,                             // 成功回合数（你说话+我回答=1 次）
  "fails": 1,                             // 失败回合数（你说不对/反对）
  "firstAt": "2026-10-21T…",
  "lastAt": "2026-10-29T…",
  "ageBucket": "week",                    // 便于「时间近优先」
  "state": "active|demoted|voided"
}
```

## 3. 在线流程（每回合）

```
你/群友发言
 ① 取词器：从这句话取词（≥2 字中文都算候选，常规词按「出现次数太多」屏蔽）
 ② 撞记忆：先 deep/important.jsonl → 不够再常规层（relations/user/notes/sayings/diary/guide…）
 ③ 关系册闸门：私聊只看「跟这个人有关」的；群聊只看「跟本群+本发言人有关」的（social 四分区）
 ④ 提词器研判：
       - 这批候选里，哪一条讲的是「同一件具体的事」？（不是字面相似）
       - 多义：候选 ≥2 条且时间跨度 > N 天 → 时间近优先；仍不确定 → 直接问「是哪一次」
       - 有【现在】时间，用来判断「多久以前」并决定措辞（上周 / 上个月 / 昨天）
 ⑤ 我按正常对话说出来（内部打标：本次 recallId → important.id，只写运行态）
```

## 3b. 取词器的两条硬规矩（丹阳 2026-10-29 补定）

1. **广取，不靠检索端收窄**：是不是「真回忆」由提词器判，取词器只负责**多给候选**（默认 5–8 条，按年龄分桶各取，保证**至少 2 条 ≥7 天**）。检索端为了"准"而收窄，会把老记忆永远挡在门外（实测 155 条命中里 147 条在 1 天内，>1 月为 0）。
2. **非人话不进候选**：注入块、其他插件/子代理的设定 prompt（「你是…助手」「下面是使用者的设定」「行为设定」等）**不是交流**，一律不进样本、不进取词池。判据：一轮用户消息里出现这类模板，或整段是长指令而非说话。

## 4. 回话后的判定（这是计分环节）

| 你的反应 | 记什么 |
| --- | --- |
| 「对 / 是 / 没错」或顺着用下去 | **成功** +1 |
| **否认**：没这回事 / 你记错了 / 瞎编 | **失败** +1，并进记错表 |
| **反对**：不是这个 / 不对 / 讲偏了（事有，但我说岔了） | 只记 `objections`，**不算失败、不进记错表** |
| 沉默 / 转移话题 | **不加分**（丹阳 2026-10-29 定） |

> 三种反应分开是丹阳 2026-10-29 定的：「可以否认或者反对，人也有记错的时候」。
> 分开的理由：否认=记忆本身不对；反对=记忆对但我表述偏了——后者不该让那条记忆背锅，否则会误杀。

判定落地：显式措辞走规则（关键词+否定极性），语义模糊时用小模型判一次；只判「上一回合我是否在做回忆」，不扫全对话。

**止步判据**：同一 topic 累计 `count` 达 2（两次来回）→ 升为「重要」；`fails` 达 2 且 `count` 不高 → 降级/标废。

## 4b. 二步法：回想 → 输出 → 再回想 → 再输出（丹阳 2026-10-29 定）

```
① 回想   取词器取 → 提词器判 → 我输出（像正常说话）
② 反应   你确认 / 反对 / 否认 / 沉默
③ 再回想 被「反对」时**必须回原文核对**（memory_recall / memory_locate），不许用「记不清」结案
④ 再输出 核对完二选一：原文对得上 → 修正说法重说一遍；对不上 → 按「否认」处理（失败 + 记错表）
```

**为什么必须有 ③④**：原文一直存在（归档 + 会话索引），所以「记不清」不是合理状态；要么我说对了，要么我真记错。
「反对」如果只记一个计数就放着，等于把一句说偏的话永远留在那儿——所以反对是**临时态**，下一步必须去查。

**现状**：①②③④ **已实现**（2026-10-29）：
- 反对时自动按门牌取原文（`verifyExcerptOf`：有 session+seq 就 `memory_recall` 取那一段；没有就明说「位置未知/取不到」，不猜），本轮注入 `<puppet_verify>` 摆出原话，要求二选一（修正表述 / `memory_cue demote`）。
- 「我也能置疑」做成**置信度分级**（不另开通道）：`confidence < 0.5` 不提（记 dismissed）、`0.5–0.7` 说时带「（我不太确定）」、`>0.7` 正常说。
- 测试：`test/inject-cue.mjs` 20 项（含反对闭环）、`test/cueprompt.mjs` 38 项（含置信度分级）。

## 5. 已确认的回忆 = 事件（可查）

每次回忆（无论成败）落一条事件到 `deep/recall-events.jsonl`：

```jsonc
{
  "ts": "2026-10-29T15:40:00+08:00",
  "session": "session-…",
  "scene": "private|group",
  "speaker": "personId（群聊时必填）",
  "importantId": "imp-…|null",
  "candidates": ["hash1","hash2"],
  "myTextFingerprint": "sha1(前 80 字)",   // 用来把「你的反应」对到这次回忆
  "verdict": "confirmed|denied|silent",
  "at": "…"
}
```

用途：以后查「这件事我们是什么时候确认过的」「我哪几次记错了」。

## 5b. 记错表：取词器自己的黑名单（丹阳 2026-10-29 定）

提词器判「不构成回忆 / 被你否认」的记忆，进 **`deep/misrecall.jsonl`**，下次取词**直接跳过**。

```jsonc
{
  "hash": "<记忆条目 hash>",      // 跳的是「这条 × 这个话题」
  "topic": "邮件被批",             // 取词主题（不含 topic 时按整条记忆封）
  "pattern": ["邮件","那个","上次"],// 触发这几次误取的词
  "fails": 2,
  "lastAt": "2026-10-29T…",
  "expiresAt": "2026-11-28T…"     // 30 天后自动失效，防止永久误杀
}
```

**两条纪律（我建议这样定，你否掉就改）：**

1. **是按「条目 × 话题」跳，不是永久封杀整条记忆**——同一条记忆换个话题还该能取。一次误判就把一条好记忆永久拉黑，代价太大。
2. **带过期**（默认 30 天）：人会变、说法会变，黑名单不能是终身判决。过期后允许再试一次，再失败再进。

## 5c. 关系 × 事件 × 记忆的扩散（丹阳 2026-10-29 定）

取词命中一条之后，允许**沿关系与事件走一跳**，把相邻的记忆也带出来：

```
人/群（social entities + edges）
   ↕ 参与
事件（recall-events / 日记里的具体事）
   ↕ 指向
记忆条目（relations / notes / sayings / 图片）
```

**只走一跳**，不走多跳、不做权重衰减——理由同 B-64：多跳和衰减需要「长期命中日志」当校准，我们现在没有，硬做就是拍脑袋。扩散命中的条目必须**能解释**（结果里写「因为与 X 同一事件/同标签」）。


## 6. 时间必须以「现在」为准

- 提词器 prompt / 取词器 prompt **必须带 `【现在】YYYY-MM-DD HH:mm 周X（时区）`**（沿用 B-87），否则「上次/最近/那次」无从判断。
- 命中内容按年龄分桶：`<1h / 1d / 1w / 1m / 更早`；**时间近的优先**，老记忆只在词汇强命中时才提。
- 时间拿不到就省略该行，不写相对词（现有纪律）。

## 7. 多选消歧

- 触发条件（三条同时）：候选 ≥2 条、主题相近、时间跨度 > 7 天。
- 话术：一句话问清，例如「你说的是上周那个邮件的，还是更早那次？」
- **不打断优先**：能取最近那条就把话说下去，只在「两条都像、答错代价大」时才问。
- 一次会话里最多问一次（避免变成审问）。

## 8. 验收判据（先有基线才谈改进）

| 判据 | 怎么测 | 现在 |
| --- | --- | --- |
| 跨时段真回忆率 | 离线 probe：仅统计「跨会话或 >1 天的命中被真用到」的比例 | **16.7%**（2026-10-29 实测：60 回合 / 10 个） |
| 条目利用率 | 命中条目里真被用到的比例 | **8.4%**（跨时段；含上下文重复时是 30.6%） |
| 误取率 | 命中但被你否认 / 提了不相干的事的比例 | 未测 |
| 消歧打扰率 | 每 N 回合问一次「是哪一次」 | 未测（目标 ≤1/20 回合） |
| 沉默不计分 | 沉默回合 count 不涨 | 单测断言 |

**2026-10-29 基线实测（probe v5，60 回合、49 个会话）**

```
跨时段命中回合 60；其中真回忆 10（16.7%）
跨时段命中条目 155 条，真用到 13 条（8.4%）
按年龄分桶（命中 / 用到）：
  1d-1w  147 / 13 = 8.8%
  1w-1m    8 /  0 = 0.0%
  >1m      0 /  0 = —
```

**两个结论（比数字本身重要）**

1. **75% → 16.7% 证明「真回忆」大部分是上下文重复**：把「比这轮早 ≥1 天」作为回忆门槛后，命中条目利用率从 30.6% 掉到 8.4%。
2. **瓶颈在「取不到」而不是「取了没用」**：155 条命中里 147 条是 1 天以内的，一周以上的只有 8 条、一个月以上 0 条。现在的检索（时间近因 + 短文本 BM25）**几乎不往老记忆那边走**——所以取词器第一件要做的事不是"更准"，是**给老记忆留配额**（强制保留 ≥1 条跨周命中），否则永远测不出老记忆有没有用。

**2026-10-29 追加实测（probe v7，两条腿取候选）**

```
候选来源：BM25 近 3 + 年龄腿中龄 2（1–7 天）+ 老龄 2（≥7 天）
回合 60；真回忆回合 43（71.7%）；候选 330 → 用到 54（16.4%）
中龄候选 120 条 / 用到 0（0.0%）
老龄候选  30 条 / 用到 0（0.0%）
```

**结论：年龄腿在这个样本里完全没有产出。** 三个原因要一起看：

1. 年龄腿只能靠「共享稀有二字词」排序，相关性弱，提词器判「不是同一件事」——符合预期，它本来就没有主题知识。
2. 样本是同一个项目连着几天的会话，「老」= 几天前的同一主题，本来就不构成「想起来了」。
3. 会话只覆盖 10-25 → 10-29，≥7 天的条目极少（60 回合里总共只有 30 条老龄候选）。

**对设计的影响：`重要 ≠ 老`。** 重要的判据是「被双方确认过」，不是时间久；年龄配额先不做，或只在「确认过的事很老」时才需要。

**样本质量问题**：49 个会话里混进了别的插件/子代理的注入型 prompt（刷B站、QQ 机器人设定），被当成人话。下一版要按 session 来源过滤。


**改进的判定方式**：同一批离线样本（当前 49 会话 / 60 回合），改动前后跑同一 probe，比「跨时段真回忆率」。

**2026-10-29 追加实测（probe v8，复放线上取词/提词；不依赖连聊）**

背景：丹阳说「我们连续聊的有点少，想验证有点麻烦」→ 把历史会话里的用户消息当输入，
直接跑线上同一套 `pickCandidates` + `judge`（本地探针 `cue-probe8.mjs`）。

```
回合 24（从 50 个会话里按修改时间取样）
判为回忆 14（58.3%）；其中置信度 0.5–0.7：1
候选 97 条，平均 4.04 条/回合
来源分布：事件 0 / 重要 0 / 常规 97
事件候选出现的回合：0
疑似「复述他这句话」（提示与他原话重合≥2 词）：10
扣掉自我复述后的真回忆：4（16.7%）
```

**三条读数**：
1. **两条新腿现在都是空的**——`deep/important.jsonl` 还没有一条（升重要要「两次来回确认」，我们还没确认过任何一条）；事件表只有 1 条手写总结，撞不上样本。所以 97 条候选全来自常规检索。
2. **提词器偏松**：58.3% 里 10 条是「我把他的原话复述回去」，扣掉后真回忆 16.7%，与 v5 基线一致——说明新代码目前没改变真实命中率（符合预期：腿空）。
3. **该加两道闸**：①输入门槛（太短/无信息量的句子不取词）；②自我复述过滤（候选条目文本≈用户这句时，不算回忆）。这两条不进代码前，58% 这个数会一直骗人。

**v8b：加了两道闸之后的同一批样本**

两道闸：①输入门槛 `worthCueing`（<4 字/词、没有两个二字词就不取词）；②提词器加「信息增益」要求 + 近逐字复述过滤（`selfEchoOf`：Dice ≥0.88 或「他的话≤12 字且候选完整包含」）。

```
回合 24（被输入门槛挡掉 4，分母 20）
判为回忆 3（15.0%）；扣掉复述后 2（8.3%）
候选 80 条，平均 3.33 条/回合（加闸前 4.04）
来源分布：事件 0 / 重要 0 / 常规 80
```

**读数**：判中率从 58.3% 收到 15.0%，剩下的 3 条抽看都是**有信息增益**的（例：「他定过紧急联系约定：小号掉线时通过 QQ 机器人通道联系」），不是复述。跟 v5 基线 16.7% 同一量级，但噪声少得多。**样本只有 24 回合，只当趋势，不当结论**；要定论得跑 100 回合以上。

**第一次调闸的教训（记下来，别再犯）**：`selfEchoOf` 一开始阈值取 0.6，把真回忆一起杀了——判中率掉到 5.0%，比基线还差。原因很清楚：**记忆记的就是同一件事，词面天然重合**；0.6 这种「像就杀」的阈值等于惩罚「记得准」。改成 0.88 + 短句包含，才站住。

**2026-10-29 定稿的分工（陆陆续续改出来的，记在这里免得再问）**

- **取词器**：每回合取新词，不看有没有待判（待判不挡取词）。
- **提词器**：只看「上一段 + 这一段」——`judge` 收 `prevUserText`，提示词里写明「更早的不算」；他要是指代（「那个」「不是这个」），以这两段为准理解。
- **待判只有一格**：上一段没表态 → 当场作废（不挂到 24 小时过期，也不记账：沉默不加分）；判过成败的那回合不再抛新回忆。

**2026-10-29 补的账：沉默也记事件**

原来只在他表态（确认/否认/反对）时才落事件，所以「回忆了几次、几次没被用」算不出来。现在：
- **提出一条回忆就落一条事件**（`verdict=silent`，带 `id`）；
- 他表态后用 `updateEvent` 改**同一条**的 `verdict`（并同步月索引计数），不新增行；
- 「沉默不加分」不变——沉默只是**没有判定**，不是没发生。

**v8c：换成中文分词之后（同一批 24 回合）**

```
门槛：至少两个中文词（分词后判断，不再看字数）
回合 24（被门槛挡掉 10，分母=14 过闸回合）
判为回忆 4（28.6%）；其中 1 条是复述，扣掉后真回忆 3（12.5%）
候选 56 条，平均 2.33 条/回合（分词前 3.33）
来源分布：事件 0 / 重要 0 / 常规 56
```

**读数**：候选从 3.33 降到 2.33，判中率从 15.0% 升到 28.6%，抽出来的 4 条**都带信息增益**（紧急联系约定、双向打通验证、第一次测音乐）。真回忆率 12.5%，比上一版 8.3% 高，仍低于 v5 的 16.7%——但样本只有 14 个过闸回合，只能说方向对，不能说提升成立。

**门槛变严的代价要记着**：24 回合里挡掉 10 个（分词前挡 4 个）。挡掉的多是 URL、纯链接、两三个字的短句——按设计该挡；但这也意味着**真实会话里四成左右的回合不会取词**。如果以后觉得「该想起来的时候没想起来」，先查这里，而不是先调提词器。

## 9. 与现有功能的关系

| 现有 | 关系 |
