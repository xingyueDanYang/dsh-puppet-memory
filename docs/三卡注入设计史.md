# 三卡 / 自我层注入设计史

> 记录「为什么现在是这个节奏」。代码里只留实现，旧方案留在这里，别塞回注释和 README 版本历史。

## 现在（2026-11-22 定，0.50.0 起）

| 场景 | 三张卡（规则/核心/状态） | 自我层 |
|---|---|---|
| 会话首轮（含重启后第一轮） | 全量 | 不进（首轮只给三卡，免得一次注入太长） |
| 第 2 轮 | — | 补一次（同轮只发一次） |
| 第 100 / 200 / … 轮 | 全量 | 全量 |
| 压缩后那一轮 | 全量补一次 | 全量补一次 |
| 卡内容改过 | 立即全量（同一轮也发） | 全文改了也立即发 |
| 同一轮的后续工具步骤 | 跳过 | 跳过 |
| 其它轮 | 不发 | 不发 |

等级（inject.core.levels）：

- strong → 全文
- weak → 一行提示（「状态卡在场，本轮只给提示；全文用 memory_core action=get target=state 取。」）；但**内容改过**的那轮仍给全文
- 当前配置：core/rules = strong，state = weak

实现：cardInjectMode（要不要发）、cardPartText（发全文还是提示）、lastCardsTurn / lastSelfHash（同轮守位与内容指纹）。

## 旧设计（0.42.7，2026-11-17；2026-11-22 删除）

要点：**四张卡各走各的班次**，把「缺得够多」当补的判据——

1. 压缩后各强补一次全文（那时在上下文开头，注意力最足）。
2. 平时按**缺失比例**判断：核心卡/自我层每 5 轮查一次、缺 >20% 才强补；规则卡每 10 轮、缺 >10%；状态卡每 20 轮（或有工具调用时），只弱提示。
3. 其余轮次只给一句弱提示。

### 为什么废

- **判据不可验**：缺失比例依赖上下文文本比对，数值随会话内容漂移，「该补没补」很难复现；改成固定轮次（1/100）后，diag 一行就能验。
- **实际效果是重复**：四张卡在长会话里被反复重灌（0.43 时代实测过同内容多份），而模型的记忆依赖首轮和压缩后那两下，中间的「补」多数没产生新信息。
- **配置半死**：levels 里 state/self = weak 的语义与「缺口补」纠缠，2026-11-22 前实际不生效（注入处直接读原文）。

### 还留着的部分

- 「提示层按层补」（0.42.7 第②条，关系/笔记/知识/常言按缺口补）**仍在用**，那是补充层，不是三张卡；missingRatioOf 仍服务于它。
- 压缩后补全文的时间点也保留（现在并入「压缩后那一轮全量」这条规则）。
